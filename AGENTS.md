# AGENTS.md

This file provides guidance to the AI agent when working with code in this repository.

## Stack

- Rails 8.1 / Ruby 3.3.14, MySQL, Hotwire (Turbo + Stimulus), Tailwind CSS via tailwindcss-rails with daisyUI, importmap JS (no JS bundler build step).
- Search: ransack (`@q = Model.ransack(params[:q])`) — models must declare `ransackable_attributes` / `ransackable_associations` explicitly (see `Student`, `SemesterKlass`). Pagination: kaminari (`.page(params[:page])`). State machines: aasm.
- Background jobs, cache and Action Cable are database-backed (solid_queue / solid_cache / solid_cable) against the production databases.

## Commands

- Setup: `bin/setup` (idempotent: bundle install, `db:prepare`, then starts `bin/dev`; `--skip-server`, `--reset`).
- Dev server: `bin/dev` (starts Rails plus the Tailwind watcher via `Procfile.dev`; new styles will not appear without the watcher).
- Full local checks: `bin/ci` (see `config/ci.rb`: rubocop, bundler-audit, importmap audit, brakeman, `bin/rails test`, and test-env `db:seed:replant`).
- Tests: `bin/rails test` (Minitest + `fixtures :all`). Single test: `bin/rails test test/models/semester_test.rb` or `bin/rails test test/models/semester_test.rb:18`. Authenticated controller tests use `sign_in_as(users(:one))` from `test/test_helpers/session_test_helper.rb`.
- Done bar: before calling a change done, run `bin/rails test` and `bin/rubocop`; run the full `bin/ci` only when asked.
- Lint: `bin/rubocop` — style is rubocop-rails-omakase defaults, no overrides (`.rubocop.yml` only inherits the gem config).
- Security checks: `bin/bundler-audit`, `bin/importmap audit`, `bin/brakeman`.
- Data preflight: `bin/rails data:integrity` reports duplicate business keys and orphan rows; run it before applying new unique indexes/foreign keys in production.
- One-off CSS build: `bin/rails tailwindcss:build` (writes `app/assets/builds/tailwind.css`); the Dockerfile runs `assets:precompile` for production.
- CI: `.github/workflows/ci.yml` runs `bin/ci` on pull requests and pushes to `main` (MySQL 8 service, `RAILS_ENV=test`); a successful run on `main` triggers CD.
- Deploy: Kamal. `.github/workflows/cd.yml` is triggered by a successful CI `workflow_run` on `main` and checks out the exact commit CI verified — it no longer deploys on push in parallel with the checks; do not push to `main` casually. Aliases: `bin/kamal console|shell|logs|dbc` (`config/deploy.yml`).

## Architecture

- Tutoring-school admin app. Root is `admin/dashboards#index` (overview) and nearly all routes live under `namespace :admin` (`config/routes.rb`); only session, passwords and `/up` are public.
- Domain chain: `School` → `Campuse` (校区) → `Semester` (per school, ordered by `seq`; `current` / `history` are date-based, while `related_next_semester` / `related_previous_semester` / `related_history_semesters` follow `seq` order so overlapping or gapped date ranges cannot break the chain) → `SemesterKlass` (班级 = semester + grade + subject + genre + seq) → `Course` (课次, `seq`, `start_date`) → `Attendance` (one per course × `KlassStudent`). `SemesterKlass` creates `times` courses in an `after_create`; `Course#start!` creates an Attendance for every enrolled student and refuses to start out of order (`previous_courses_started?`), so only the first unstarted course can be opened. `Student` / `Teacher` belong to a campuse; `Guardian`, `DaySchool`, `Grade`, `Subject`, `GradeSubject` are supporting tables.
- Access control: `User` → `UserCampuse` (role `admin` / `manager`, JSON `grade_ids`) → `Campuse`; `Current` (ActiveSupport::CurrentAttributes) holds the session and delegates `user`. `Current.user.grades_by_campuse` / `subjects_by_campuse` limit which grades and subjects a manager sees.
- Request context: `AdminController#set_current_context` populates `Current.campuse`, `Current.school`, `Current.semester` from the session (ActiveSupport::CurrentAttributes); `AdminController#campuse_semester_klasses` is the write/read scope for class actions (current campus + **current semester** + allowed grades), so operating on another semester's class requires switching the semester first — that is deliberate, not a missing filter; switching happens in `Admin::CampusesController#switch_thread_campuse` and `Admin::SemestersController#switch_thread_semester`. Views read these directly too (hidden fields and filter forms under `app/views/admin/`) — check views as well as controllers when changing scope.
- State machines (aasm): `Attendance` has 7 statuses with `mark_absent` / `mark_personal_leave` / `mark_sick_leave` / `mark_filled` / `mark_quit` / `mark_transfer` / `mark_rejoin`; `mark_quit` and `mark_transfer` only cascade to later started courses and update `KlassStudent` (`in` / `out` / `transfer`); the student stays in the class list. `Course#start!` generates attendance for every non-archived enrollment based on its status (`in`→normal, `out`→quit, `transfer`→transfer), so later courses keep the quit/transfer state. `Admin::AttendancesController#mark` dispatches `"mark_#{params[:status]}!"`; `#transfer` marks the source attendance transfer and enrolls the student in a target class of the same campus/semester/grade (the class page renders one transfer drawer, opened by per-cell buttons via `transfer_drawer_controller.js`); `KlassStudent#reinstate!` undoes the current quit/transfer streak and, for transfers, archives the recorded target enrollment. Removing a student from a class archives the `KlassStudent` (`archived_at`) instead of deleting it, so attendance history remains; the class page can restore archived enrollments.
- Reporting: `Admin::SemesterKlassesController#statement` builds a `StatementReport` (plain Ruby class in `app/models`, not an AR model) computing per-class 新增/拓科/预留/未预留 counts, rates and rosters via `Semester#related_*` scopes; `StatementSheet` exports it to xlsx. `reserve` (预留下学期) enrolls `in` students into a same-subject class of `related_next_semester` — pick an existing class or create a new one — via `Student#join_klass(..., allow_grade_mismatch: true)`; it deliberately does NOT change the student's grade (bulk grade promotion is a separate action, `Admin::StudentsController#promote`). `copy` / `copy_create` duplicate classes into another semester.
- Excel: exports use caxlsx via plain Ruby classes in `app/models` (`AttendanceWorkbook` / `AttendanceSheet`, `StatementSheet`, `StudentImportTemplate`); student import (`Admin::StudentsController#import`) accepts .xlsx via roo (`Student.add_by_xlsx`) or pasted text (`Student.add_by_text`), skipping rows with mismatched grade/day-school or duplicates.
- `StudentReferral` tracks 老带新 referrals (one referrer per referred student, no self-referral), reported by `Admin::ReferralsController`. `Admin::GuidesController#show` renders `docs/user_guide.md` in-app via Redcarpet — update that guide when changing user-facing flows.
- School curriculum: `Admin::GradeSubjectsController#index` renders a grade×subject matrix for `Current.school` and `Current.semester`; `GradeSubject` now carries `semester_id` and `times`. `sync` incrementally creates/deletes combinations for the current school+semester and updates each combination's `times` (default class lesson count), refusing to disable combinations that already have classes in that semester. The class form auto-fills 课次 from this setting via `klass_times_controller.js`. `Grade`/`Subject` are global dictionaries managed on the same page via `Admin::GradesController` / `Admin::SubjectsController` (create/update/destroy with in-use deletion guards); the school form now only links to this page.
- UI: daisyUI + Tailwind v4 with Turbo/Stimulus; shared navbar / alert / footer / drawer partials live in `app/views/admin/shared/`. New users see a 新手引导 wizard on the dashboard (`admin/shared/_guide_wizard` + `guide_wizard_controller.js`) until they finish or skip it — tracked per account in `users.guide_completed_at`; steps come from `Admin::DashboardsController#guide_steps` and admin-only steps are filtered by role.

## Gotchas

- After a migration that adds or removes columns, restart `bin/dev`: the running Puma caches each model's column list, so it keeps selecting the dropped column (`Unknown column ... in 'field list'`) until restart. A fresh `bin/rails runner` process is a quick way to confirm the schema is fine.
- Archived enrollments: `KlassStudent` has **no `default_scope`**. The `klass_students` associations (on `SemesterKlass` / `Student`) and the `active` scope exclude `archived_at` rows; use `all_klass_students`, `archived_klass_students`, or `.unscoped` when archived rows are needed (e.g. `Student#join_klass` restoring a removed enrollment). Add `.active` to direct `KlassStudent.where(...)` queries that should ignore removed students.
- `Current.campuse`, `Current.school`, and `Current.semester` hold the logged-in user's currently selected campus/school/semester, set in `AdminController#set_current_context`. Admin controllers must scope queries by these — never by all of the user's campuses.
- `Campuse` is the intentional model name (misspelled singular): table `campuses`, join model `UserCampuse` (`user_campuses`), routes `campuses`. Do not rename or "fix" it.
- All UI copy is Chinese — keep new views, notices, and labels in Chinese.
- Auth is Rails 8 cookie-session auth via the `Authentication` concern: every controller requires login unless it declares `allow_unauthenticated_access`.
- Local MySQL connects via socket `/tmp/mysql.sock`, user root, no password (`weituo_development` / `weituo_test`). Production uses separate cache/queue/cable databases; `config/database.yml` declares `migrations_paths` for them (`db/cache_migrate`, `db/queue_migrate`, `db/cable_migrate`) but those directories are not present in the repo yet — create them if you add migrations for those databases; connection URLs come from `*_DATABASE_URL` secrets via `.kamal/secrets`.
- `config/deploy.yml` runs Solid Queue inside Puma (`SOLID_QUEUE_IN_PUMA`) on a single web host; recurring jobs are in `config/recurring.yml`.
- `node_modules/` is NOT gitignored — hundreds of files under `node_modules/daisyui` are committed, so npm upgrades produce large diffs.
- daisyUI is vendored in three places: the tracked `node_modules/daisyui` package, the standalone bundles `app/assets/tailwind/daisyui.mjs` + `daisyui-theme.mjs` (loaded via `@plugin "./daisyui*.mjs"` in `app/assets/tailwind/application.css` because the Tailwind standalone CLI cannot resolve npm packages), and `vendor/javascript/daisyui.js` pinned by `config/importmap.rb` (`pin "daisyui"`, comment still `@5.5.17`, not imported anywhere). Keep all three in sync when upgrading.
- `app/assets/builds/*` and `public/assets` are gitignored — CSS and compiled assets are generated, never committed.
- `db/seeds.rb` deletes ALL business data (including users and sessions) before generating demo data (2 campuses, 4 semesters, 180 students; demo logins `admin` / `user1`–`user3`, password `password`); it aborts in production. `bin/ci` runs `env RAILS_ENV=test bin/rails db:seed:replant`.
- Work lands directly on `main` (no PR flow); a push to `main` auto-deploys after CI passes — never push without an explicit request. Commit messages are short and often Chinese; no strict convention beyond that.
