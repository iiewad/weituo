# AGENTS.md

This file provides guidance to the AI agent when working with code in this repository.

## Stack

- Rails 8.1 / Ruby 3.3.14, MySQL, Hotwire (Turbo + Stimulus), Tailwind CSS via tailwindcss-rails with daisyUI, importmap JS (no JS bundler build step).
- Search: ransack (`@q = Model.ransack(params[:q])`) — models must declare `ransackable_attributes` / `ransackable_associations` explicitly (see `Student`, `SemesterKlass`). Pagination: kaminari (`.page(params[:page])`). State machines: aasm.
- Background jobs, cache and Action Cable are database-backed (solid_queue / solid_cache / solid_cable) against the production databases.

## Commands

- Setup: `bin/setup` (idempotent: bundle install, `db:prepare`, then starts `bin/dev`; `--skip-server`, `--reset`).
- Dev server: `bin/dev` (starts Rails plus the Tailwind watcher via `Procfile.dev`; new styles will not appear without the watcher).
- Full local checks: `bin/ci` (see `config/ci.rb`: rubocop, bundler-audit, importmap audit, brakeman, `bin/rails test`, and test-env `db:seed:replant`).
- Tests: `bin/rails test` (Minitest + `fixtures :all`). Single test: `bin/rails test test/models/semester_test.rb` or `bin/rails test test/models/semester_test.rb:18`. Authenticated controller tests use `sign_in_as(users(:one))` from `test/test_helpers/session_test_helper.rb`.
- Done bar: before calling a change done, run the relevant test files (e.g. `bin/rails test test/models/reservation_test.rb`) and `bin/rubocop`; the full `bin/rails test` suite is slow — run it only when asked, and the full `bin/ci` only when asked.
- Lint: `bin/rubocop` — style is rubocop-rails-omakase defaults, no overrides (`.rubocop.yml` only inherits the gem config).
- Security checks: `bin/bundler-audit`, `bin/importmap audit`, `bin/brakeman`.
- Data preflight: `bin/rails data:integrity` reports duplicate business keys and orphan rows; run it before applying new unique indexes/foreign keys in production.
- One-off CSS build: `bin/rails tailwindcss:build` (writes `app/assets/builds/tailwind.css`); the Dockerfile runs `assets:precompile` for production.
- CI: `.github/workflows/ci.yml` runs `bin/ci` on pull requests and pushes to `main` (MySQL 8 service, `RAILS_ENV=test`); a successful run on `main` triggers CD.
- Deploy: Kamal. `.github/workflows/cd.yml` is triggered by a successful CI `workflow_run` on `main` and checks out the exact commit CI verified — it no longer deploys on push in parallel with the checks; do not push to `main` casually. Aliases: `bin/kamal console|shell|logs|dbc` (`config/deploy.yml`).

## Architecture

- Tutoring-school admin app. Root is `admin/dashboards#index` (overview) and nearly all routes live under `namespace :admin` (`config/routes.rb`); only session, passwords and `/up` are public.
- Domain chain: `School` (登录/分组壳 — only maintains its `campuses` and `user_campuses` grants, no business data) → `Campuse` (校区 — **full data isolation**: semesters, grades, subjects, grade-subject configs, klasses, students, teachers and day schools are all per campus) → `Semester` (per campus, ordered by `seq`; `current` is a per-campus flag on `semesters.current`, kept at exactly one per campus by `Semester`'s `after_save` / `after_destroy` callbacks — marking one current clears its siblings, and when none is current the smallest-`seq` semester takes over; `history` and `related_next_semester` / `related_previous_semester` / `related_history_semesters` follow `seq` order) → `SemesterKlass` (班级 = semester + phase + grade + subject + genre + seq; 一阶段 / 二阶段 per semester, the same genre+seq may repeat across phases, and `name` is prefixed with 一期 / 二期) → `Course` (课次, `seq`, `start_date`) → `Attendance` (one per course × `KlassStudent`). `SemesterKlass` creates `times` courses in an `after_create`; `Course#start!` creates an Attendance for every enrolled student and refuses to start out of order (`previous_courses_started?`), so only the first unstarted course can be opened. `Student` / `Teacher` belong to a campuse; `Grade` / `Subject` / `GradeSubject` are per-campus dictionaries too (`level` / `name` and `code` / `name` unique within a campus; `Campuse` `has_many :semesters/:grades/:subjects/:grade_subjects`, all `dependent: :destroy`, so deleting a campus wipes them); `Guardian` and `DaySchool` are supporting tables. Semester/Grade/Subject/GradeSubject used to belong to School and were moved to Campuse by migration 20261128120000 (it wiped all business data — the app was not live yet).
- Access control: `User` → `UserCampuse` (role `admin` / `manager`, JSON `grade_ids`) → `Campuse`; grants are managed in 用户管理, except that `Admin::SchoolsController#update` auto-grants the acting admin (role `admin`, **empty `grade_ids`** — a new campus has no grade dictionary of its own yet) on every campus it creates, otherwise a new campus would never appear in the navbar campus switcher (which lists `Current.user.campuses`); grades created later in 年级科目管理 are auto-appended to every `admin` grant of the current campus (`Admin::GradesController#grant_grade_to_campus_admins`), and `Admin::UsersController#sanitize_grade_ids!` strips grade ids that don't belong to the row's campus on create/update (server-side twin of the per-campus chip filtering in `user_campuses_controller.js`). `Current` (ActiveSupport::CurrentAttributes) holds the session and delegates `user`. `Current.user.grades_by_campuse` / `subjects_by_campuse` limit which grades and subjects a manager sees.
- Request context: `AdminController#set_current_context` populates `Current.campuse`, `Current.school`, `Current.semester` from the session (ActiveSupport::CurrentAttributes) — the semester is validated against `campuse.semesters` and falls back to `Semester.current(campuse.id)`, and `Current.school` is simply `campuse.school` (School is a shell); the navbar semester switcher lists the current campus's semesters. `AdminController#require_semester_context` guards semester-less campuses: when `Current.semester` is nil, semester-dependent pages redirect admins to 学期管理 (managers to the dashboard) instead of 500-ing on `Current.semester.id`; controllers that work without a semester are listed in `SEMESTER_OPTIONAL_CONTROLLERS`. `AdminController#campuse_semester_klasses` is the write/read scope for class actions (current campus + **current semester** + allowed grades), so operating on another semester's class requires switching the semester first — that is deliberate, not a missing filter; switching happens in `Admin::CampusesController#switch_thread_campuse` and `Admin::SemestersController#switch_thread_semester`. Views read these directly too (hidden fields and filter forms under `app/views/admin/`) — check views as well as controllers when changing scope.
- State machines (aasm): `Attendance` has 8 statuses with `mark_absent` / `mark_personal_leave` / `mark_sick_leave` / `mark_filled` / `mark_quit` / `mark_transfer` / `mark_rejoin`; `mark_quit` and `mark_transfer` only cascade to later started courses and update `KlassStudent` (`in` / `out` / `transfer`); the student stays in the class list. `transfer_in` (转入) is a read-only state written only by the transfer action via `update!(status:)` — it declares no aasm events in or out, so any `mark_*!` on it raises `AASM::InvalidTransition` (natural read-only enforcement; it is never in `MARKABLE_STATUSES`). `Course#start!` generates attendance for every non-archived enrollment based on its status (`in`→normal, `out`→quit, `transfer`→transfer; a transferred-in `in` enrollment whose `transfer_in_seq` is later than the course gets read-only `transfer_in` instead of normal, so backfill-starting pre-entry courses stays correct), so later courses keep the quit/transfer state. `Admin::AttendancesController#mark` dispatches `"mark_#{params[:status]}!"`; `#transfer` marks the source attendance transfer and enrolls the student in a target class of the same campus/semester/grade via `Student#join_klass(..., transfer_from: @sk)`; the entry course aligns with the source transfer-out course (`join_course_seq_for` = the larger of source seq + 1 and the target's first unstarted seq, falling back to the first unstarted seq when the aligned course doesn't exist), and the target's already-started courses before the entry course are marked read-only `transfer_in` (`Student#mark_transferred_in_attendances`) instead of carrying over the source's attendance — the source keeps its own real attendance, and a reverse transfer back likewise preserves the original class's real attendance (only missing/quit/transfer rows become `transfer_in`). `KlassStudent.transfer_source_klass_id` / `transfer_in_seq` record the latest transfer-in source and entry course, driving the target class's per-cell 转入 detail (the class page renders one transfer drawer, opened by per-cell buttons via `transfer_drawer_controller.js`); `KlassStudent#reinstate!` undoes the current **quit** streak only (transfers are terminal: to move a student back, transfer them out of the target class — the guard allows a `transfer`-status enrollment — and `join_klass(..., reinstate: true)` flips it back to `in`). Removing a student from a class archives the `KlassStudent` (`archived_at`) instead of deleting it, so attendance history remains; the class page can restore archived enrollments.
- Reporting: `Admin::SemesterKlassesController#statement` builds a `StatementReport` (plain Ruby class in `app/models`, not an AR model) computing per-class 预留/未预留 counts, rates and rosters via `Semester#related_*` scopes; `StatementSheet` exports it to xlsx (报表与菜单名「班级预留报表」，新增/拓科 指标已移除). `reserve` (预留下学期) only writes a `Reservation` (student + target semester + grade + subject + genre + optional teacher + source semester and source class; `source_semester_id` is stored directly so the 源学期 survives source-class deletion; unique per student/semester/subject) for `in` students of `related_next_semester` — it no longer enrolls them or creates a class, and deliberately does NOT change the student's grade (bulk grade promotion is a separate action, `Admin::StudentsController#promote`). `Admin::ReservationsController#index` lists every reservation as one row per student (ransack filters: student name, source semester, target semester / grade / subject / genre / teacher, plus a `status` param for pending / generated); `generate` acts on a group (same semester / grade / subject / genre / phase / teacher — teacher-less reservations form their own group), takes the class teacher from the `teacher_id` param (required), creating one class per group (phase carried over from the source class) and enrolling the group via `Student#join_klass`, marking `reservations.semester_klass` and backfilling `teacher`. **学员年级与班级年级一致才可进班**: `Student#join_klass` has no grade-mismatch escape hatch (the old `allow_grade_mismatch` kwarg is gone), so generate / batch_enroll only enroll students already promoted to the target grade (bulk promotion is the separate `Admin::StudentsController#promote`, run first); unpromoted reservations are skipped and stay pending, and a group with zero promoted students creates no (empty) class — the operator is told to promote first. The report's 预留 rate deliberately still counts actual attendance in next semester's same-subject class, not reservation records. `copy` / `copy_create` duplicate classes into another semester. 年级报表 (`Admin::GradeReportsController#index/#export` + `GradeReport` / `GradeReportSheet`, plain Ruby in `app/models`) is a separate per-semester × per-grade report of 在班/新增/拓科/回流 (新增 = no enrollment in any earlier semester; 回流 = no enrollment in the previous semester but some earlier one; 拓科 = enrolled previous semester and the semester subject set both continues ≥1 previous subject and adds ≥1 new subject — switching subjects without continuing does not count; enrollment = `KlassStudent.active` with `status: "in"`; history loads all grades campus-wide while rows are limited to `allowed_grade_ids`).
- Excel: exports use caxlsx via plain Ruby classes in `app/models` (`AttendanceWorkbook` / `AttendanceSheet`, `StatementSheet`, `ReferralSheet`, `StudentImportTemplate`); student import (`Admin::StudentsController#import`) accepts .xlsx via roo (`Student.add_by_xlsx`) or pasted text (`Student.add_by_text`), skipping rows with mismatched grade/day-school or duplicates and returning `[created, skipped, failures]` — the controller lists each failure (row, name, reason) in the flash: the list is stored in `Rails.cache` by `FlashDetails` (plain Ruby in `app/models`) and the flash only carries a `details_token`, because the cookie session overflows at ~4KB; `admin/shared/_alert` renders it as a scrollable list.
- 日校: `Admin::DaySchoolsController` is admin-only and manages `DaySchool` per `Current.campuse` (`name` unique within a campus); students reference it by name during import, and day schools that still have students cannot be deleted.
- `StudentReferral` tracks 老带新 referrals (one referrer per referred student, no self-referral), surfaced by the 推荐看板 dashboard in `Admin::ReferralsController` (`#index` = stat cards + top-10 ranking + referred-grade distribution + a server-paginated detail table (page-number window + per-page 20/30/50/100 selector, mirroring the Students index), filterable by referrer grade and a `period` of month/quarter/year — both apply board-wide — plus a `name` search that fuzzy-matches the referrer **or** referred student's name but deliberately filters **only the detail table**, leaving cards/ranking/distribution on the grade+period scope; `#export` streams `ReferralSheet` to xlsx where the summary sheet reflects grade+period and the detail sheet additionally honors `name`). `Admin::GuidesController#show` renders `docs/user_guide.md` in-app via Redcarpet — update that guide when changing user-facing flows.
- Campus curriculum & semesters: 学期管理 is a standalone page on top-level `/admin/semesters` routes (`index/create/update/destroy` + member `switch_thread_semester`; `Admin::SemestersController`, campus-admin only via `require_admin`, modeled after 日校管理) — the school-nested semesters routes are gone and school nesting now only contains `campuses`. Deleting a semester cascades its classes/courses/attendances, `GradeSubject` configs and reservations (`dependent: :destroy`) and nullifies `students.in_semester_id`; the view shows an unrecoverable-deletion confirmation. `Admin::SchoolsController` (学校管理) now only maintains the school name and its campuses — the form has no semester block (the `semesters` stimulus controller was deleted). Bootstrap mode (no campus exists system-wide): any logged-in user is redirected to 学校管理 to create the first campus (auto-granted `admin`), then creates semesters in 学期管理. `Admin::GradeSubjectsController#index` renders a grade×subject matrix for `Current.campuse` and `Current.semester`; `GradeSubject` carries `campuse_id`, `semester_id` and `times`, and validates grade/subject/semester all belong to the same campus. `sync` incrementally creates/deletes combinations for the current campus+semester and updates each combination's `times` (default class lesson count), refusing to disable combinations that already have classes in that semester. The class form auto-fills 课次 from this setting via `klass_times_controller.js`. `Grade`/`Subject` are per-campus dictionaries managed on the same page via `Admin::GradesController` / `Admin::SubjectsController` (create/update/destroy with in-use deletion guards). Campus-scoped validations elsewhere: student import matches 入学学期 by name and grade `level` against **the current campus's** dictionaries (so does promote / `Student#update_grade`), teacher subject must exist 在该校区开设, and a class's semester must belong to the same campus.
- UI: daisyUI + Tailwind v4 with Turbo/Stimulus; shared navbar / alert / footer / drawer partials live in `app/views/admin/shared/`. `search_select_controller.js` turns a server-rendered `<select>` into a search input + dropdown (filters by option text or optgroup label, writes the choice back to the select and re-dispatches `change`); the class form uses it for 教师, and its 年级 / 班型 are radio buttons styled as buttons (`input.btn` with `aria-label`), so `student_multiselect_controller.js` reads the grade from the wrapping container's checked radio rather than from a select value. New users see a 新手引导 wizard on the dashboard (`admin/shared/_guide_wizard` + `guide_wizard_controller.js`) until they finish or skip it — tracked per account in `users.guide_completed_at`; steps come from `Admin::DashboardsController#guide_steps` and admin-only steps are filtered by role; step 1 links to 学期管理 (`admin_semesters_path`). The sidebar 系统设置 group lists 学期管理 (campus admins only, hidden in bootstrap mode) alongside 学校管理 / 年级科目管理 / 日校管理 / 用户管理.

## Gotchas

- After a migration that adds or removes columns, restart `bin/dev`: the running Puma caches each model's column list, so it keeps selecting the dropped column (`Unknown column ... in 'field list'`) until restart. A fresh `bin/rails runner` process is a quick way to confirm the schema is fine.
- Archived enrollments: `KlassStudent` has **no `default_scope`**. The `klass_students` associations (on `SemesterKlass` / `Student`) and the `active` scope exclude `archived_at` rows; use `all_klass_students`, `archived_klass_students`, or `.unscoped` when archived rows are needed (e.g. `Student#join_klass` restoring a removed enrollment). Add `.active` to direct `KlassStudent.where(...)` queries that should ignore removed students.
- `Current.campuse`, `Current.school`, and `Current.semester` hold the logged-in user's currently selected campus/school/semester (the semester always belongs to the current campus), set in `AdminController#set_current_context`. Admin controllers must scope queries by these — never by all of the user's campuses.
- `Campuse` is the intentional model name (misspelled singular): table `campuses`, join model `UserCampuse` (`user_campuses`), routes `campuses`. Do not rename or "fix" it.
- All UI copy is Chinese — keep new views, notices, and labels in Chinese.
- Auth is Rails 8 cookie-session auth via the `Authentication` concern: every controller requires login unless it declares `allow_unauthenticated_access`.
- Local MySQL connects via socket `/tmp/mysql.sock`, user root, no password (`weituo_development` / `weituo_test`). Production uses separate cache/queue/cable databases; `config/database.yml` declares `migrations_paths` for them (`db/cache_migrate`, `db/queue_migrate`, `db/cable_migrate`) but those directories are not present in the repo yet — create them if you add migrations for those databases; connection URLs come from `*_DATABASE_URL` secrets via `.kamal/secrets`.
- `config/deploy.yml` runs Solid Queue inside Puma (`SOLID_QUEUE_IN_PUMA`) on a single web host; recurring jobs are in `config/recurring.yml`.
- `node_modules/` is NOT gitignored — hundreds of files under `node_modules/daisyui` are committed, so npm upgrades produce large diffs.
- daisyUI is vendored in three places: the tracked `node_modules/daisyui` package, the standalone bundles `app/assets/tailwind/daisyui.mjs` + `daisyui-theme.mjs` (loaded via `@plugin "./daisyui*.mjs"` in `app/assets/tailwind/application.css` because the Tailwind standalone CLI cannot resolve npm packages), and `vendor/javascript/daisyui.js` pinned by `config/importmap.rb` (`pin "daisyui"`, comment still `@5.5.17`, not imported anywhere). Keep all three in sync when upgrading.
- `app/assets/builds/*` and `public/assets` are gitignored — CSS and compiled assets are generated, never committed.
- `db/seeds.rb` deletes ALL business data (including users and sessions) before generating demo data (2 campuses with fully isolated data — each gets its own 4 semesters (seq 1–4, the 3rd current), grades 7–9, subjects 数/英/物/化 and GradeSubject configs for the current + next semester (`times` 16); 180 students; `UserCampuse.grade_ids` reference each campus's own grades; demo logins `admin` / `user1`–`user3`, password `password`); it aborts in production. `bin/ci` runs `env RAILS_ENV=test bin/rails db:seed:replant`.
- Work lands directly on `main` (no PR flow); a push to `main` auto-deploys after CI passes — never push without an explicit request. Commit messages are short and often Chinese; no strict convention beyond that.
